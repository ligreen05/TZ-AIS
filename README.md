## 🎯 Назначение системы

АИС «Складской учёт» предназначена для автоматизации процессов:

- приёмки товаров от поставщиков;
- размещения товаров по местам хранения;
- внутренних перемещений между зонами склада;
- комплектации и отгрузки покупателям;
- списания товаров (порча, недостача, истечение срока);
- проведения инвентаризаций;
- формирования отчётности по движению, остаткам и оборачиваемости;
- контроля минимальных остатков.

**Цели создания:**

- сокращение времени оформления складских операций;
- повышение точности учёта остатков;
- снижение потерь и недостач;
- обеспечение руководства достоверной аналитикой;
- централизованное хранение данных с разграничением доступа.

## 🏗 Архитектура

Проект построен по **трёхслойной архитектуре**:

```
┌─────────────────────────────────────────────────┐
│  Blueprints (HTTP-слой)                         │
│  ─ Аутентификация, роутинг, рендер шаблонов    │
│  ─ Валидация через WTForms                      │
│  ─ Проверка ролей через @require_role           │
└────────────────┬────────────────────────────────┘
                 │
┌────────────────▼────────────────────────────────┐
│  Services (бизнес-логика)                       │
│  ─ create_receipt, create_shipment...          │
│  ─ cancel_receipt, cancel_shipment...          │
│  ─ apply_inventory                              │
│  ─ apply_stock (работа с остатками)             │
└────────────────┬────────────────────────────────┘
                 │
┌────────────────▼────────────────────────────────┐
│  Models (данные)                                │
│  ─ SQLAlchemy-модели                            │
│  ─ Индексы, связи, константы                    │
└────────────────┬────────────────────────────────┘
                 │
┌────────────────▼────────────────────────────────┐
│  SQLite / PostgreSQL                            │
└─────────────────────────────────────────────────┘
```

**Ключевые принципы:**

- **Разделение ответственности** — HTTP-логика отделена от бизнес-логики.
- **Единая точка транзакций** — контекстный менеджер `transaction()`.
- **Защита от N+1** — `lazy="joined"` и `lazy="selectin"` на связях.
- **Идемпотентность** — повторная отмена документа отклоняется.
- **Аудит** — все значимые действия пишутся в `ActionLog`.

**1. Клонируй проект или распакуй архив:**


**2. Создай виртуальное окружение:**

```bash

```

**3. Активируй venv:**

**Windows (PowerShell):**
```powershell
.\.venv\Scripts\Activate.ps1
```


```bash
pip install -r requirements.txt
```

**5. Создай базу данных с демо-данными:**

```bash
python init_db.py
```

## 🚀 Запуск

### Режим разработки

```bash
python app.py
```

Сервер запустится на `http://127.0.0.1:5000`.

Открой в браузере: **http://127.0.0.1:5000**

### Production-режим

Для production используй **gunicorn** (Linux) или **waitress** (Windows):

```bash
# Linux
gunicorn -w 4 -b 0.0.0.0:5000 "app:app"

# Windows
waitress-serve --port=5000 app:app
```

### Переменные окружения

Для production задай:

```bash
FLASK_SECRET_KEY=<длинная-случайная-строка>
DATABASE_URL=postgresql://user:pass@host/dbname
LOG_LEVEL=INFO
```

## 🗄 Модель данных

### Основные сущности

```
Role ────┐
         └── User ──────┐
                        │
Category ──┐            │
Unit ──────┼─ Product ──┤
           │            │
Supplier ──┼─ ReceiptDoc ─── ReceiptItem
           │
Customer ──┼─ ShipmentDoc ── ShipmentItem
           │
Warehouse ─┼─ TransferDoc ── TransferItem
           │
           ├─ WriteOffDoc ── WriteOffItem
           │
           ├─ InventoryDoc ── InventoryItem
           │
           └─ StorageLocation ─ Stock ─ Product
```

### Ключевые особенности

- **`Stock`** — остаток товара на конкретном месте хранения. Уникальный индекс `(product_id, warehouse_id, location_id)`.
- **`ActionLog`** — журнал всех действий с человеко-понятными названиями.
- **Отмена документов** — поля `is_cancelled`, `cancelled_at`, `cancelled_by` в каждом документе.
- **Индексы** — на все FK, поля поиска (`sku`, `name`, `number`), даты, статусы.

## 🛡 Безопасность

### Реализованные механизмы

| Угроза | Защита |
|---|---|
| **SQL-инъекции** | Только ORM (SQLAlchemy), экранирование LIKE |
| **XSS** | Jinja2 autoescape, security headers |
| **CSRF** | Flask-WTF токены во всех формах |
| **Brute force** | Строгие правила валидации пароля |
| **Session hijacking** | HttpOnly + SameSite cookies, session_protection=strong |
| **Clickjacking** | `X-Frame-Options: DENY` |
| **MIME sniffing** | `X-Content-Type-Options: nosniff` |
| **Open redirect** | Проверка `next` URL после логина |
| **Пароли** | Хеширование `pbkdf2:sha256` |

### Заголовки безопасности

Каждый ответ содержит:

```
X-Content-Type-Options: nosniff
X-Frame-Options: DENY
Referrer-Policy: strict-origin-when-cross-origin
Permissions-Policy: geolocation=(), microphone=(), camera=()
```

### Роли и права

- Проверка ролей через декоратор `@require_role(...)` — `abort(403)` при недостатке прав.
- Отмена документов и управление пользователями доступны только определённым ролям.
- Аудит через `ActionLog` — все значимые действия фиксируются.

### Что делать в production

1. **Задай `FLASK_SECRET_KEY`** через переменную окружения.
2. **Включи HTTPS** — `Talisman(force_https=True)`.
3. **Используй PostgreSQL** вместо SQLite.
4. **Запускай через gunicorn/waitress**.
5. **Настрой регулярные бэкапы БД**.
